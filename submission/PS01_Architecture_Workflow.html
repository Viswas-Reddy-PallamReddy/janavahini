Technical architecture and workflow · Problem Statement 1: Real-Time Crowd Monitoring and Congestion Management

Janavahini: how the system is built and how an alert flows

Counters on every road, gate and junction estimate crowd density, look a minute ahead, and pass warnings back along the pilgrim route to the police who can act. Decisions are made on the devices, so alerts keep working when the network or the command centre fails.

2 · Workflow inside every node · repeated once a second

Count, look ahead, combine warnings, signal, pass back

1 · CountSensors at both ends of the ~25 m patch count people crossing in and out.
2 · DensityPeople in patch = in − out; density = people ÷ patch area.
3 · Look aheadForecast = density now + rate of rise × 60 s (rate used only once the patch is busy, ≥ 1.5 persons/m²).
4 · ListenReceive the states of downstream nodes over the mesh; weight each by the share of this road's flow that heads there (from the route map).
5 · CombineTake the strongest of: own forecast, weighted downstream warnings, and the ICCC command (if the network is up).
6 · Dead neighbour?"Unknown is not safe": keep its last warning, listen one hop further, report "NODE DOWN – send staff".
7 · SignalSet the three-colour light: green, amber or red (NDMA-aligned levels).
8 · Pass backBroadcast state to upstream neighbours and, via the gateway, to the server and ICCC.

4 · Hardware, software, infrastructure and integration
ItemRequirement
Hardware per nodeESP32 board with LoRa (SX1276); two VL53L1X ToF sensors (not needed where CCTV counts exist); IP65 three-colour signal tower; IP65 enclosure; mains adapter with backup battery.
QuantityAbout 250 nodes for the full site (68 compartments, 20 junctions, 10 Nagaras); 10–15 for the pilot. Gateway node(s) connect to the server over USB/serial.
SoftwareOpen-source ESP32 firmware, FastAPI backend and web dashboard; runs on one server or VM at the ICCC.
InfrastructurePower and mounting points at gates, roads and junctions; barricades narrowing gates to single or double file for accurate counting.
Integration(a) Read crowd counts from existing CCTV/AI analytics. (b) Push node states, alerts and node-down events to ICCC dashboards and RTGS via a documented REST/WebSocket API. (c) Accept ICCC inflow commands. (d) Staff messages in Telugu and English.
5 · Data and security
  • Data: only counts and densities per patch, node health and alert logs. No images leave the sensor; no faces, phones or personal data.
  • Security: authenticated node messages so a spoofed radio cannot raise or clear alerts; TLS on all API traffic; API keys and role-based access for ICCC operators; an audit log of every command; holds released only by an operator; hosting in the RMC or state data centre following CERT-In guidelines.
